# Quy ước i18n cho web

## Ngôn ngữ và routing

- Ngôn ngữ hỗ trợ lấy từ `Language` của `@hiveshelf/shared`.
- Tiếng Việt (`vi`) là ngôn ngữ mặc định và nguồn fallback.
- URL giao diện luôn có tiền tố locale: `/vi/...`, `/en/...`.
- Locale hợp lệ trên URL được ưu tiên hơn cookie và header.
- Với URL không có tiền tố: cookie `NEXT_LOCALE` hợp lệ → `Accept-Language` → `vi`.
- Cookie ghi nhớ lựa chọn tối đa một năm, áp dụng cho đường dẫn `/`.
- Thuộc tính `<html lang>` phải khớp locale trên URL.
- Locale giao diện độc lập với ngôn ngữ nội dung sách từ API.

Cấu hình dùng chung nằm trong `apps/web/src/i18n`. Root layout nằm tại
`apps/web/src/app/[locale]/layout.tsx`; cấu hình request đọc locale bằng
`next/root-params`, không dùng `requestLocale` đã deprecated.

## Tổ chức bản dịch

File dịch nằm trong `apps/web/messages/{locale}/{namespace}.json`.

| Namespace | Nội dung                                               |
| --------- | ------------------------------------------------------ |
| `common`  | Giao diện dùng chung, metadata, hành động và lỗi chung |
| `auth`    | Đăng nhập, đăng ký và các luồng xác thực               |
| `reader`  | Giao diện đọc sách                                     |
| `catalog` | Danh mục, tìm kiếm và thông tin sách                   |

Namespace chưa sử dụng có thể chứa `{}`. Khi thêm namespace mới, cập nhật bộ nạp
`messages.ts`, danh sách namespace bắt buộc trong script kiểm tra và các test liên quan.

## Đặt tên khóa

- Dùng khóa có ý nghĩa theo cấu trúc namespace → tính năng → thành phần.
- Dùng camelCase, ví dụ `common.actions.retry`, `auth.login.submit`.
- Namespace là tên file; không lặp lại namespace bên trong JSON.
- Dùng object lồng nhau, không đặt dấu chấm trong tên thuộc tính JSON.
- Không dùng nguyên câu hiển thị làm khóa.
- Thêm, đổi hoặc xóa khóa ở cả `vi` và `en` trong cùng PR.
- Không để bản dịch rỗng hoặc chỉ chứa khoảng trắng.

## Sử dụng bản dịch

Async Server Component dùng `getTranslations`:

```tsx
import { getTranslations } from "next-intl/server";

const t = await getTranslations("common");
```

Client Component dùng `useTranslations` bên trong `NextIntlClientProvider`:

```tsx
import { useTranslations } from "next-intl";

const t = useTranslations("common");
```

- Không viết cứng chuỗi giao diện trong component.
- Dịch cả placeholder, tooltip, aria-label và metadata.
- Log kỹ thuật không bắt buộc dịch; nội dung sách không đưa vào JSON dịch giao diện.
- Dùng interpolation cho biến, ICU cho số nhiều; không nối các mảnh câu.
- Các ngôn ngữ phải dùng cùng tên biến nội suy và rich-text tags.
- Dùng `t.rich` khi bản dịch cần chứa thành phần React.
- Không dùng `dangerouslySetInnerHTML` để hiển thị bản dịch.

Ví dụ chuỗi `Trạng thái API: <strong>{status}</strong>`:

```tsx
t.rich("home.apiStatus", {
  status: liveness.status,
  strong: (chunks) => <b>{chunks}</b>,
});
```

## Fallback và kiểm tra chất lượng

Messages tiếng Anh được merge sâu lên messages tiếng Việt. Khóa thiếu ở tiếng Anh
sử dụng bản dịch tiếng Việt; chuỗi rỗng không tự kích hoạt fallback.

Fallback giúp giao diện hoạt động khi thiếu bản dịch. CI vẫn phải báo lỗi nếu hai
ngôn ngữ lệch khóa, kể cả khi runtime có thể dùng fallback.

Script `apps/web/scripts/check-i18n.mjs` đọc file JSON gốc trước khi merge. Script
phát hiện khóa thiếu/thừa, namespace thiếu, cấu trúc khác nhau, giá trị không hợp lệ,
bản dịch rỗng và JSON sai cú pháp. Có lỗi thì trả exit code `1`.

Script chưa kiểm tra cú pháp ICU hoặc sự tương ứng của biến nội suy và rich-text
tags; các mục này cần được review và kiểm tra khi render.

## Điều hướng và chuyển ngôn ngữ

- Link và điều hướng nội bộ có locale dùng `@/i18n/navigation`.
- Các API khác như `notFound` và `useSearchParams` vẫn lấy từ Next.js.
- `LanguageSwitcher` phải giữ pathname, query string, tham số lặp và hash.
- Component dùng `router.replace` với `scroll: false`; không thêm mục lịch sử mới.
- Lựa chọn ngôn ngữ được đồng bộ vào cookie `NEXT_LOCALE`.
- Matcher hiện bỏ qua API, tài nguyên nội bộ và đường dẫn có dấu chấm.
  Nếu thêm route nội dung có dấu chấm, cần cập nhật matcher.

## Ngày và số

- Dùng helper trong `src/i18n/format.ts` hoặc formatter của next-intl.
- Không tự ghép ngày hoặc chèn dấu phân cách số.
- `vi` dùng quy tắc `vi-VN`; `en` dùng quy tắc `en-US`.
- Múi giờ mặc định là `TIME_ZONE = "Asia/Ho_Chi_Minh"`, dùng chung với cấu hình request.
- Locale quyết định cách trình bày; múi giờ quyết định ngày, giờ của một thời điểm.
- Chuỗi thời gian biểu diễn một thời điểm phải xác định múi giờ, chẳng hạn ISO 8601
  có `Z` hoặc UTC offset. Với helper, chuyển chuỗi này thành `Date` trước khi gọi.

```ts
formatNumber(1234567.89, locale);
formatNumber(0.75, locale, { style: "percent" });
formatDate(new Date("2026-11-24T10:00:00Z"), locale);
```

## Lỗi API

Quy ước cho các luồng gọi API tiếp theo:

- API trả mã lỗi ổn định qua trường `code`.
- Web ánh xạ các code đã biết sang khóa dịch.
- Code không nhận diện được dùng thông báo lỗi chung đã dịch.
- Không hiển thị trực tiếp thông báo kỹ thuật từ API cho người dùng.

## Rendering và CSP

Proxy chịu trách nhiệm tạo nonce mới theo request, ghi đè nonce/CSP từ client và
chuyển request headers đã cập nhật xuống renderer khi gọi next-intl. Phải giữ
response của next-intl để bảo toàn redirect, rewrite và cookie, đồng thời đặt CSP
trên response trả về. Layout đọc nonce để truyền cho ThemeProvider.

Thiết kế nonce theo request và việc layout đọc `headers()` yêu cầu render động;
trang chủ còn khai báo `force-dynamic`. Chỉ thêm `generateStaticParams` không đủ để
bật SSG/ISR với thiết kế hiện tại.

Muốn dùng SSG/ISR cần thiết kế CSP/cache phù hợp trước. Không dùng chung HTML chứa
nonce giữa các request. Kiểm tra CSP trong trình duyệt production ngoài các test
Vitest; test response chuyển hướng không chứng minh nonce đã đến renderer.

`alternateLinks` đang tắt. Hreflang và canonical sẽ được xử lý trong card SEO.

## Kiểm tra tại máy và CI

Chạy từ thư mục gốc với dependencies và biến môi trường web đã được thiết lập:

```bash
pnpm --filter @hiveshelf/shared build
pnpm --filter @hiveshelf/web i18n:check
pnpm --filter @hiveshelf/web lint
pnpm --filter @hiveshelf/web typecheck
pnpm --filter @hiveshelf/web test
pnpm --filter @hiveshelf/web build
```

Shared cần được build trước vì web và script import từ output của package này.
Lệnh `typecheck` chạy `next typegen` trước `tsc --noEmit`, bảo đảm type của
routing và `rootParams.locale()` được sinh trên checkout mới.
Bước sinh type nạp Next.js config nên cần các biến môi trường như khi build web.

CI chạy bước `Check translation keys` sau `Run checks`, khi shared đã được build.
Các test i18n được chạy cùng test workspace. Vitest cần
`test.server.deps.inline: ["next-intl"]` để xử lý import của thư viện khi test điều hướng.

Kiểm tra trình duyệt cho cả `/vi` và `/en`: nội dung, metadata, `<html lang>`,
chuyển ngôn ngữ giữ URL, cookie, hydration và theme. Kiểm tra `/` với cookie,
Accept-Language và trường hợp không có lựa chọn để xác nhận thứ tự ưu tiên.
